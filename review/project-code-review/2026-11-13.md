# 项目代码审查

审查基线为 `main` 的 `5d73ea455cd3a5ce435874fdf6d28d87b5933010`。
优先修复发布确认范围、模型指纹权限隔离，以及可能覆盖运行产物的并发启动问题。

审查覆盖执行可靠性、权限与隔离、数据发布与远程读取、前端交互与性能、评测正确性与质量门。
发现来自静态代码与现有测试覆盖。浏览器行为、性能开销及真实模型调用未作运行验证。

### 模型回答可触发调用目录外的文件读取

读回发生在凭据扫描之后，宿主已有的 SVG 可能作为新作品落盘。
将读回范围限定为本次调用的产物目录，并在落盘前扫描最终内容。

### 调度器启动可改写仍在运行的轮次

启动恢复未验证原执行进程是否存活。启动本机调度器时，仍活跃的手动轮次可能被标记为取消
并提前同步。只有进度文件时，恢复还可能删除轮次目录。确认原执行进程已退出后再恢复。

### 界面报错后，外置执行器仍可能发起收费调用

执行器离线时，Web 等待超时返回 `503`，请求继续处于 `pending`。执行器恢复后可以认领该请求，
重复提交还可能留下多条待执行请求。给未认领请求设定期限，原子处理过期与认领，
并提供已认领请求的可查询状态。
[运行 API](../../src/app/api/run/route.ts#L161) ·
[请求认领](../../src/core/requests.ts#L308)

自动同步先于 AI 评审，手动导出也只检查轮次的 `inProgress`。最终分数写入后，再同步遇到
已有导出目录会报内容冲突。将导出就绪状态绑定到评审终态，覆盖正常结束和重启续评。
[轮次收尾](../../src/core/runner.ts#L211) ·

该入口因此缺失按配置克隆和核对 `origin` 的行为。路径指向另一个克隆时，导出和显式推送

## P2–P3 · 其余发现

### 执行可靠性

- 已认领请求的处理异常只记日志，可能使请求一直停在 `claimed`。回执写盘失败还可能令
  请求处理悬挂。为认领和回执建立可恢复的状态转换，明确处理副作用未知的请求。
  [请求处理](../../src/bin/runner.ts#L143) · [请求清理](../../src/core/requests.ts#L325)
- 首次进度写入失败后，串行写入队列仍允许调用 `onStarted`。API 可能返回 `202`，随后取消接口
  找不到该轮。首次写入成功应作为继续执行和确认启动的前提。
  [启动回执](../../src/core/runner.ts#L170) · [串行写入](../../src/core/serial-writes.ts#L13)

### 会话与凭据

- 普通页面和 API 可轮换会话凭据，只有会话 API 下发新 cookie。首次轮换发生在其他入口时，
  旧凭据在 60 秒宽限后失效。将轮换限定在可下发 cookie 的端点。
  [会话校验](../../src/core/auth/session.ts#L71) · [会话 API](../../src/app/api/session/route.ts#L35)
- 设备更新和吊销各自读取并重写整张表。旧快照可能在吊销完成后恢复设备记录。
  配对码兑换也采用分开的读写步骤。把读、校验和写入放在同一互斥范围内。
  [设备表](../../src/core/auth/devices.ts#L40) · [配对窗口](../../src/core/auth/pairing.ts#L50)
- 外置执行器通过共享卷接收明文 profile key。请求文件未显式限制为 `0600`，
  进程退出时未结请求可能保留密钥。限制文件权限，并使认领、过期和清理原子化。
  [凭据请求](../../src/core/requests.ts#L155) · [文件写入](../../src/core/requests.ts#L415)

### 数据同步与远程读取

- 自动同步和 CLI 绕过面板同步锁。并发时可能相互暂存文件或覆盖同步台账。
  在共享操作入口加跨进程锁，并限定 Git 暂存路径。
  [自动同步](../../src/core/run/post-sync.ts#L13) · [CLI 同步](../../src/bin/sync-data.ts#L292) ·
  [Git 暂存](../../src/core/sync/data-repo-git.ts#L161)
- 远程 SVG 的临时 `404` 或 `5xx` 响应会进入 24 小时缓存。上游恢复后，同一展台进程仍可能
  返回作品不存在。成功响应沿用现有缓存期限，错误响应立即淘汰或使用较短期限。
  [请求缓存](../../src/core/data-source/fetch-pool.ts#L60) ·
  [远程 SVG](../../src/core/data-source/remote.ts#L162)

### 评测正确性与提交质量门

- SVG 抽取可能漏掉合法的自闭合嵌套，或把注释和 CDATA 中的标签文本识别为边界。
  所有候选校验失败时仍返回无效片段，可能覆盖有效文件并被记为 `ok`。
  按 XML 语法识别片段边界，并仅接受规范化后通过校验的作品。
  [候选选择](../../src/core/svg.ts#L74) · [标签扫描](../../src/core/svg.ts#L94) ·
  [状态记录](../../src/core/run-attempt.ts#L64)
- 指纹样本按请求强度聚合。能力目录改变生效强度后，追加样本会覆盖整套样本的生效档位，
  核验也可能继续用旧档位基线。按生效强度分区或过滤，保留历史样本的原档位。
  [样本存储](../../src/core/model-fingerprint/store.ts#L128) ·
  [核验准备](../../src/core/model-fingerprint/collect.ts#L303)
- Codex 的 `thread/start` 或 `turn/start` 响应超时被记为 `error`。`turn/start` 响应晚到时，
  现有中断分支也无法处理该轮。统一截止错误分类，并定义启动状态未知时的清理行为。
  [调用启动](../../src/adapters/codex.ts#L56) ·
  [RPC 超时](../../src/adapters/codex-app-server.ts#L108)
- 预提交密钥检查从索引取路径，实际读取工作树。部分暂存时，待提交快照可能含密钥而扫描仍
  通过。预提交检查应读取索引中的文件内容，并覆盖索引与工作树内容不一致的测试用例。
  [密钥扫描](../../scripts/check-secrets.ts#L59) · [提交钩子](../../lefthook.yml#L11)

### 前端状态、导出与性能

- SSE 重连前后完成总数相同，时间线可能一直缺少新轮次。单件作品页也可能在 AI 评审完成后
  保留初始结论。按轮次、作品及结果版本触发刷新。
  [看板刷新](../../src/app/components/run-status/useRunProgress.ts#L17) ·
  [作品页](../../src/app/view/ArtViewerFoot.tsx#L21)
- 结果集导出把成功作品的资源读取或净化失败显示为「已脱敏，未发布」，页脚仍标为成功。
  以 `svgFile === null` 判断脱敏，单独显示资源读取失败。
  [缩略图准备](../../src/app/components/export/export-image.ts#L28) ·
  [导出图框](../../src/app/components/export/result-set-svg.ts#L230)

  该日期实际使用 UTC−4。按所选日期计算偏移，在夏令时切换日展示实际适用的偏移。
  [导出标题](../../src/app/components/export/ExportMenu.tsx#L104)
- 待评审徽章才调用 `useLiveProgress`。同一卡片更新为最终结论时，条件调用可能遗留实时订阅。

- 缩略图对同一份 SVG 完整净化两次。保留一个净化入口，并在净化失败时淘汰对应缓存。
  重复执行已确认，滚动与主线程开销尚未量测。
