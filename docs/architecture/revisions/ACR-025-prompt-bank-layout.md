## 动机

- 题面分布在三个源码目录，英文展示数据集中在另一套分组中。
- 按题组汇合题面和展示数据，降低维护单道题目和抽取文学题库的改动范围。

## 方案评估

| 方案 | 来源 | 版本 | 许可证 | 最近发布 | 维护状态 | 改造面（要动几个模块） | 维护成本 | 判定 | 否决理由 |
|---|---|---|---|---|---|---|---|---|---|
| 沿用现有 TypeScript 静态模块与显式索引 | - | 5.9 | Apache-2.0 | - | - | 4 个模块 | 复用编译和校验链 | adopt | - |

> **结论**：用 TypeScript 显式索引登记题库，按题组放置数据。

- 回退迁移提交及对应文档提交。
- 本地配置和运行记录无需迁移。

## 人工确认

### 方案摘要

1. 将内置题目统一到题库目录，应用和国际化入口跟随更新。
2. 保留题目原文、稳定标识和运行记录。
3. 将同一题组的中文数据和英文展示数据一起维护。
4. 通过全量数据快照核对，回退可恢复旧目录。
5. 使用当前工具链和 TypeScript 静态模块。
