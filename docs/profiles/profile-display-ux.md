# 上游 Profile 的看板呈现与交互设计

本文定义非默认 profile（下称"上游"）在首页时间线、模型弹窗、大图详情页与"跑一次"菜单中的
呈现与交互。领域模型与运行时见 [`codex-profiles-design.md`](codex-profiles-design.md)，本文取代其 §9。

## 1. 现状问题

| 位置 | 问题 | 后果 |
|---|---|---|
| 首页时间线 | 行键 `rowKeyOf` 为 `cli/model/promptId`，不含 profile | 同模型经三个上游的结果挤进同一行同一格；格子四角按强度取第一张，另两张不可见 |
| 模型弹窗 | 标题只有 `cli · model`；副标题按卡片数报"N 个强度" | 三个上游的 low 被报成"3 个强度"，看不出各卡来自哪个上游 |
| 结果卡片 | 上游只出现在截断的 `label` 里 | 显示名较长时被省略号截掉，无法区分上游，也无从查看上游信息 |
| 大图详情页 | 元信息无上游 | 单独分享的作品丢失上游归属 |
| 跑一次 | 按 `cli/model` 分组，强度按钮按列落位 | 同模型不同上游的同名强度按钮落在同一列、互相重叠；上游只能靠矩阵里逐条登记的目标间接选择 |

## 2. 呈现原则

- 上游是与 CLI、模型、强度并列的比较维度，不是目标显示名的一部分；界面统一称"上游"。
- 登录态是默认上游，界面上不显示标记，与引入 profile 之前完全一致。
- 上游的可见标识只有一种：**上游徽章**（§3）。所有位置复用同一徽章，点击都打开同一张
  **上游信息卡**（§4）。
- 颜色只作辅助：每个上游一个由名字散列出的固定色点，徽章文字始终存在，色盲与导出图不依赖颜色。
- 公开视角只显示可公开字段（§4.2）；接口地址、查询参数、key 状态只给配对设备。

## 3. 上游徽章

```
[● kedaya · GPT稳定分组「禁蒸馏」0.07]
```

- 文字：显示名（`label`，缺省为 `name`）。超出宽度时中间截断，保留首尾，尾部通常是倍率，
  如 `profile-kedaya-GPT稳…「禁蒸馏」0.07`；完整显示名放在 `title`。
- 色点：`name` 的稳定散列映射到 8 色调色板；停用的上游色点为空心。
- 元素：`<button type="button" aria-haspopup="dialog">`，可 Tab 聚焦，回车或空格打开信息卡。
- 尺寸：与现有 `.badge` 同高，放在徽章行首位，即 CLI 徽章之后、模型徽章之前。

## 4. 上游信息卡

### 4.1 形态

- 桌面：锚定在徽章下方的浮层（popover），宽 320px；点击外部、Esc、再次点击徽章关闭；
  打开时焦点移入卡片，关闭后焦点回到徽章。
- 窄屏（< 768px）：底部抽屉（bottom sheet），高度自适应，最多占 70% 视口。
- 在模型弹窗内打开时层级高于弹窗；Esc 只关闭信息卡，不连带关闭弹窗。

### 4.2 内容

```
┌──────────────────────────────────────────────┐
│ ● profile-kedaya-GPT稳定分组「禁蒸馏」0.07    │  显示名
│   profile-kedaya-plus-1-005 · codex · 启用中  │  标识 · CLI · 状态
├──────────────────────────────────────────────┤
│ 上游类型  chatgpt-plus                        │
│ 分组      GPT稳定分组「禁蒸馏」               │
│ 倍率      × 0.07（官价 × 倍率）               │
│ 官网      kedaya.ai ↗                         │
│ 模型      gpt-5.5 · gpt-5.6-sol · gpt-6-sol … │  最多两行，余下折叠为 +N
├──────────────────────────────────────────────┤
│ 当天  3 次 · 成功 3 · 平均 1m50s · 折算 $0.01 │  按当前筛选的当天统计
├──────────────────────────────────────────────┤
│ 接口  kedaya.ai（仅主机名）   key 已填 09/29  │  仅配对设备
│ [只看这个上游]              [在配置页编辑 ↗]  │  编辑仅配对设备
└──────────────────────────────────────────────┘
```

| 字段 | 公开视角 | 配对设备 | 来源 |
|---|---|---|---|
| 显示名、标识、CLI、启停 | 显示 | 显示 | 配置 `profiles[]` |
| 上游类型、分组、倍率、官网 | 显示 | 显示 | 配置；契约落地后随记录进数据仓 |
| 模型清单 | 显示 | 显示 | 配置 |
| 当天统计 | 显示 | 显示 | 看板已加载的卡片现算，不另发请求 |
| 接口主机名 | 隐藏 | 显示 | 配置 `baseUrl` 只取主机名；路径与查询参数不显示 |
| key 状态 | 隐藏 | 显示 | `profile-credentials.json` 的更新时刻，不含 key |
| 在配置页编辑 | 隐藏 | 显示 | 链接 `/config#profile-<name>` |

- "只看这个上游"把首页筛选设为仅该上游，并关闭信息卡与弹窗。
- 折算成本在计价变更单落地前按官价显示并注明"未乘倍率"；落地后改为乘倍率。
- 配置里已删除、但历史结果仍引用的上游，信息卡只显示标识与"配置中已不存在"。

### 4.3 数据来源

- 看板页数据新增 `profiles: ProfileView[]`（公开字段）与配对设备专用的
  `profileSecrets: Record<name, { host; keyUpdatedAt }>`，由服务端从配置与凭据状态组装；
  公开视角不下发后者。
- 远程只读展台（`PELICAN_DATA_SOURCE=remote`）在契约支持前没有 profile 结果，也不显示徽章。

## 5. 首页时间线

- 行键改为 `cli/profile/model/promptId`，格子四角仍只按强度落位，因此每格只含一个上游。
- 行排序：CLI → 模型 → 上游（登录态在前，其余按配置顺序）→ 题目。同一模型的各上游行相邻，
  纵向即可逐轮对比。
- 行标题两行：第一行 `codex · gpt-5.5`；第二行为上游徽章与题目 id，登录态只显示题目。
  同模型相邻行的第一行降为弱色，视觉上成组。

```
codex · gpt-5.5                     │ ▣ │   │ ▣ │
animated-pelican-v1                 │   │   │   │
codex · gpt-5.5    (弱色)           │ ▣ │   │ ▣ │
[● kedaya 稳定分组 0.07] animated…  │   │   │   │
codex · gpt-5.5    (弱色)           │ ▣ │   │   │
[● kedaya 不降智 0.16] animated…    │   │   │   │
```

- 筛选菜单新增"上游"一节，可多选：登录态与每个上游各一项，记忆在本地存储。
- 图例在出现非默认上游时追加色点说明。
- 导出图的行标题按同样两行绘制，徽章画为"色点 + 文字"。

## 6. 模型弹窗

- 标题：`codex · gpt-5.5` 后接上游徽章；副标题的"N 个强度"按本行卡片数计算，行已按上游
  拆分，计数自然正确。
- 新增"对比上游"开关（仅当同一轮、同模型、同题存在其他上游时出现）。打开后弹窗主体改为
  矩阵：行 = 上游，列 = 强度，每格一张卡片，便于横向比较同一强度在不同上游下的作品。

```
                 low              high
登录态           [卡片]           [卡片]
● kedaya 0.07    [卡片]           —
● kedaya 0.16    [卡片]           [卡片]
```

- 卡片本身不变，只有表头调整（§7）。

## 7. 结果卡片

- 副标题 `subject` 对非默认上游改为 `model · effort`，不再拼接上游显示名，避免截断吞掉上游。
- 徽章行：`[codex] [● 上游] [gpt-5.5] [effort: low] [题目] [变量…]`，上游徽章可点击。
- 登录态卡片与现在逐字相同。

## 8. 大图详情页

- 标题 `viewer-title` 后接上游徽章，点击打开同一信息卡。
- 页脚抽屉在"提示词""客观参考标准"之外新增"上游"抽屉，展开即 §4.2 的内容（不含当天统计，
  改为本件作品的耗时与折算成本），便于单独分享时保留上游信息。
- 页面标题（`<title>`）追加上游显示名。

## 9. 跑一次：多选上游

### 9.1 交互

"跑一次"面板在"模型 × 强度"清单上方新增**上游条**，与模型、题目共同决定本轮范围：

```
上游  [✓ 登录态] [✓ ● kedaya 0.07] [✓ ● kedaya 0.16] [ ● kedaya 0.18] [全选]
─────────────────────────────────────────────────────────────
codex  gpt-5.5      low  high
codex  gpt-6-sol    low [high✓]
claude sonnet-5     medium        （不受上游条影响：该 CLI 不支持 profile）
─────────────────────────────────────────────────────────────
1 个目标 × 2 个上游 × 1 道题 = 2 次调用 · 预计 $0.xx     [开始]
```

以"codex gpt-6-sol high + 动态鹈鹕车 + 三个上游"为例：

1. 模型清单勾 `gpt-6-sol` 行的 `high`；
2. 题目栏勾"动态鹈鹕车"；
3. 上游条取消"登录态"，勾三个上游；
4. 页脚显示"1 个目标 × 3 个上游 × 1 道题 = 3 次调用"，点"开始"。

### 9.2 规则

- 模型清单只按 `cli · model · effort` 列出，同一组合不因上游重复出现；清单取矩阵里全部目标
  （含登记了 profile 的目标）去掉 profile 后的并集。
- 本轮调用 = 所选组合 × 所选上游。组合的 CLI 不支持 profile 时只跑登录态，页脚单独注明。
- 上游不可选的情形：已停用、未填 key、所选组合的模型不在该上游的模型清单里（清单为空视为
  不限）。不可选的项置灰并在 `title` 说明原因；部分组合不可用时照常开始，页脚列出被略过的
  组合。
- 选择记忆在本地存储；首次打开默认勾选全部可用上游与登录态。
- 预算预估按调用数计，上游不影响单价，计价变更单落地后再乘倍率。

### 9.3 服务端

- `RunSelection` 增加 `profiles: string[]`（`default` 表示登录态）；`targetIds` 改为只表示
  `cli · model · effort` 组合。
- `narrowConfig` 展开组合 × 上游：矩阵里已登记同 id 的目标沿用其显示名与超时；未登记的按
  组合合成，id 由 `buildTargetId(..., profile)` 生成，显示名按默认规则。合成目标只存在于本轮，
  不写回配置。
- 放行规则与定时轮次一致：停用、缺 key、模型不在清单内的组合在服务端再次拒绝，不信任前端。
- 定时轮次不变，仍只跑矩阵里 `enabled` 的目标。

## 10. 可访问性与响应式

- 徽章与信息卡均可键盘操作；信息卡 `role="dialog"`，带 `aria-labelledby` 指向显示名。
- 色点附 `aria-hidden`，读屏只读文字。
- 窄屏下行标题的上游徽章只显示色点与前 8 个字符，点击同样打开底部抽屉。

## 11. 改造面

| 模块 | 改动 |
|---|---|
| `src/app/components/timeline` | 行键、排序、行标题、导出图 |
| `src/app/components/card` | 上游徽章、信息卡、卡片表头 |
| `src/app/components/model-modal` | 标题徽章、对比上游矩阵 |
| `src/app/components/dashboard` | 上游筛选、页数据接入 |
| `src/app/components/run-control` | 上游条、调用数与略过提示 |
| `src/app/view` | 标题徽章、上游抽屉 |
| `src/app/api/run`、`src/core/run-selection.ts` | 组合 × 上游展开与校验 |
| `src/core` 看板页数据 | `profiles` 与配对设备专用字段 |

建议拆为两份变更单，各自可独立回滚：

1. **展示**：徽章、信息卡、首页行拆分、弹窗、卡片、大图页、筛选（`src/app` 与页数据）。
2. **跑一次多选上游**：上游条、`RunSelection.profiles`、`narrowConfig` 展开（`src/app`、`src/core`）。

## 12. 待定事项

| 事项 | 建议 |
|---|---|
| 显示名过长时是否另设短名 `shortLabel` | 先用中间截断；截断仍难分辨时再加字段 |
| "对比上游"矩阵是否进首期 | 进首期：它是多上游对比的核心视图 |
| 跑一次是否允许矩阵外的合成目标 | 允许：否则每个模型 × 强度 × 上游都要在矩阵里登记一遍 |
| 信息卡当天统计是否含失败调用的耗时 | 不含：与卡片成功率口径一致 |
