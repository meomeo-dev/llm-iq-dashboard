# 上游 Profile 的看板呈现与交互设计

本文按用户的操作流程定义非默认 profile（下称"上游"）在看板里的呈现与交互。领域模型与运行时见
[`codex-profiles-design.md`](codex-profiles-design.md)，本文取代其 §9。

## 1. 用户与流程

用户是仓库所有者，目的只有一个：**同一模型、同一强度、同一道题，经不同上游各画一张，比一比谁更聪明，
再看某个上游会不会随时间"降智"**。上游是被比较的变量，模型与强度是被固定的条件。

| 步 | 用户在做什么 | 界面 |
|---|---|---|
| 0 | 登记上游、填 key | 配置页"上游 Profile"段（已落地） |
| 1 | 定条件、选上游、发起 | "跑一次"面板（§2） |
| 2 | 等结果 | 运行状态与进度（§3） |
| 3 | 横向比较各上游的作品 | 首页格子 → 对比弹窗（§4） |
| 4 | 放大看一张，顺手换到同轮另一个上游 | 大图页（§5） |
| 5 | 看某个上游一段时间的走势 | 首页筛选（§6） |

上游的信息卡（§7）不是独立入口，只在第 3、4 步用户点到上游名字时出现。

## 2. 第 1 步：跑一次

用户的操作顺序是"先定条件，再定上游，最后开始"，面板按这个顺序从左到右排三栏：

```
┌ 范围 ──────────────┬ 题目 ─────────────┬ 上游（codex）────────────────┐
│ ● codex  gpt-6-sol │ ○ 经典版           │ ○ 登录态          未登录       │
│     low  [high]    │ ● 动态鹈鹕车       │ ● kedaya 稳定分组「禁蒸馏」0.07│
│ ○ codex  gpt-5.5   │ ○ 升级版           │ ● kedaya 不降智 0.16           │
│ ○ claude sonnet-5  │ …                  │ ● kedaya 不降智搞基版 0.18     │
│ …                  │                    │ ○ relay-x      已停用          │
├────────────────────┴────────────────────┴───────────────────────────────┤
│ gpt-6-sol · high × 3 个上游 × 1 道题 = 3 次调用 · 预计 $0.09    [开始] │
└─────────────────────────────────────────────────────────────────────────┘
```

- **范围栏**只按 `cli · model · effort` 列组合，同一组合不因上游重复出现；清单取矩阵全部目标去掉
  profile 后的并集。
- **上游栏**只在范围里勾了支持上游的 CLI（首期只有 codex）时出现，列出登录态与每个上游；勾选
  的组合里没有 codex 时整栏隐藏，面板与现在完全一样。
- 不可选的项置灰、行尾写原因：`已停用`、`未填 key`、`未登录`（登录态预检未过）、
  `没有 gpt-6-sol`（组合的模型不在该上游的模型清单里，清单为空视为不限）。
- 页脚一句话算清本轮：`组合数 × 上游数 × 题数 = 调用数`。范围里同时有 claude 目标时追加
  `claude sonnet-5 只跑登录态`。一个上游都没勾时"开始"置灰，提示"至少选一个上游"。
- 记忆：上游勾选与范围、题目一样记在本地存储；首次打开默认只勾登录态，行为与引入上游之前相同。

以"codex gpt-6-sol high + 动态鹈鹕车 + 三个上游"为例：范围栏点 `gpt-6-sol` 行的 `high`；题目栏
勾"动态鹈鹕车"；上游栏取消"登录态"、勾三个上游；页脚显示 3 次调用，点开始。

服务端：`RunSelection` 增加 `profiles: string[]`（`default` 表示登录态），`targetIds` 只表示
`cli · model · effort` 组合。`narrowConfig` 把组合 × 上游展开：矩阵里已登记同 id 的目标沿用其
显示名与超时，未登记的按组合合成，id 由 `buildTargetId(..., profile)` 生成，只存在于本轮、不写回
配置。停用、缺 key、模型不在清单里的组合在服务端再拒一次，不信任前端。定时轮次不变。

## 3. 第 2 步：等结果

- 顶栏运行状态徽章不变（`3 / 3 进行中`）。
- 展开的进度面板按上游分组，每组一行标题、组内按模型分道：

```
● kedaya 稳定分组「禁蒸馏」0.07
   gpt-6-sol · high · 动态鹈鹕车         运行中 1m20s
● kedaya 不降智 0.16
   gpt-6-sol · high · 动态鹈鹕车         运行中 1m20s
登录态
   gpt-6-sol · high · 动态鹈鹕车         排队
```

- 进度文件已有 `lanes[].profile`（ACR-014），分组不需要新数据。
- 停止按钮语义不变：停整轮。

## 4. 第 3 步：横向比较

### 4.1 首页格子不拆行

首页的行仍是 `cli · model × 题目`：用户找结果时想的是"gpt-6-sol 的动态鹈鹕车"，不是某个上游。
上游是格子里的第二层：

- 格子四角仍按强度落位。某个角有多个上游时，缩略图取登录态的作品，没有登录态取配置顺序第一个，
  角上加计数标 `×3`。
- 行标题右侧加一排色点，表示这一行出现过的上游（登录态不占点），悬停显示名字；不可点击，
  点击这一行的任何格子都进对比弹窗。
- 导出图同样画色点与 `×3`，不画上游名字。

### 4.2 对比弹窗

点格子打开的弹窗是比较的主界面。只有一个上游时布局与现在相同；有多个上游时改为
**列 = 上游、行 = 强度**，同一行的作品等高等宽并排，视线横扫即可比：

```
codex · gpt-6-sol   09/29 10:03 这一轮 · animated-pelican-v1 · 3 个上游 · 成功 3     [测评标准] [×]

          登录态              ● kedaya 稳定分组 0.07     ● kedaya 不降智 0.16      ● kedaya 不降智搞基版 0.18
high      [作品]              [作品]                     [作品]                    [作品]
low       —                   [作品]                     [作品]                    —
```

- 列标题是上游名（显示名 `label`，缺省 `name`），可点击，打开信息卡（§7）；登录态列标题不可点。
- 列序：登录态在前，其余按配置顺序；一列宽度随列数均分，最少 260px，超出横向滚动。
- 卡片表头去掉副标题里的上游名（列标题已经说明），只留时间与徽章行 `[codex] [gpt-6-sol]
  [effort: high] [题目]`；登录态的卡片与现在逐字相同。
- 卡片页脚成本一行：计价变更单落地前显示官价并注明"未乘倍率"，落地后显示 `官价 × 倍率 = 折算`。
- 筛选把某些上游隐藏时，被隐藏的列不出现，标题计数按可见列算。

## 5. 第 4 步：看单件

- 大图页标题行：`gpt-6-sol · high · ● kedaya 稳定分组「禁蒸馏」0.07 · 09/29 10:03`，上游名可点，
  打开信息卡（§7）。登录态不显示上游。
- 标题行右侧加**同轮上游切换**：同一轮、同模型、同强度、同题的其余上游作品，左右箭头或 `←` `→`
  键切换，当前项高亮。这是用户放大比较时的主要动作，不必退回弹窗再点。

```
← ● 稳定分组 0.07 · ● 不降智 0.16 · ● 不降智搞基版 0.18 →
```

- 页脚抽屉不新增；成本行同 §4.2。`<title>` 追加上游显示名，单独分享不丢归属。

## 6. 第 5 步：看走势

- 顶栏筛选菜单加"上游"一节，多选：登录态与每个出现过的上游各一项，记在本地存储。
- 只勾一个上游时，首页每格只剩该上游的作品，四角计数标消失，时间线就是这个上游的走势；
  成功率、耗时统计随筛选变化。
- 筛选也作用于对比弹窗的列与大图页的切换条。

## 7. 上游信息卡

只从 §4.2 的列标题与 §5 的标题上游名打开，用户点它时想知道的是"这是哪家、什么套餐、几折"，
其余都不放：

```
┌────────────────────────────────────────────┐
│ ● profile-kedaya-GPT稳定分组「禁蒸馏」0.07   │
│   profile-kedaya-plus-1-005 · chatgpt-plus  │
│   分组  GPT稳定分组「禁蒸馏」                │
│   倍率  × 0.07（官价 × 倍率）                │
│   官网  kedaya.ai ↗                          │
│   本件  耗时 2m10s · 官价 $0.012 · 折算 $0.0008│
│                          [在配置页编辑 ↗]    │
└────────────────────────────────────────────┘
```

- 桌面为锚定在名字下方的浮层，宽 320px；点击外部、Esc、再点名字关闭；在弹窗里打开时 Esc 只关
  信息卡。窄屏（< 768px）改为底部抽屉。
- "本件"在弹窗里指该列该轮的调用（多张时按行列出），在大图页指当前作品。
- "在配置页编辑"只给配对设备，链接 `/config#profile-<name>`。接口地址、查询参数、key 状态一律不显示：
  比较结果时不需要，公开视角也不能看。
- 配置里已删除、历史结果仍引用的上游，只显示标识与"配置中已不存在"。
- 键盘：上游名是 `<button aria-haspopup="dialog">`；信息卡 `role="dialog"`，打开时焦点移入，
  关闭后回到名字。色点 `aria-hidden`，读屏只读文字。

## 8. 数据

- 看板页数据增加 `profiles: ProfileView[]`（`name`、`label`、`upstreamType`、`group`、`website`、
  `pricing.multiplier`、`enabled`），由服务端从配置组装；不含 `baseUrl`、`queryParams`、key 状态。
- 卡片已有 `profile` 字段（ACR-013）；行键、`folderCell`、弹窗与大图页按它分组。
- 远程只读展台在契约支持前没有上游结果，所有上游元素自然不出现。

## 9. 改造面与分单

| 模块 | 改动 |
|---|---|
| `src/app/components/run-control` | 上游栏、页脚算式、选择记忆 |
| `src/app/api/run`、`src/core/run-selection.ts` | `RunSelection.profiles`，组合 × 上游展开与校验 |
| `src/app/components/run-status` | 进度面板按上游分组 |
| `src/app/components/timeline` | 格子计数标、行标题色点、导出图 |
| `src/app/components/model-modal` | 上游 × 强度矩阵、列标题 |
| `src/app/components/card` | 表头去上游名、成本行、信息卡组件 |
| `src/app/view` | 标题上游名、同轮上游切换 |
| `src/app/components/toolbar` | 上游筛选 |
| 看板页数据 | `profiles` 字段 |

拆为两份变更单，按用户流程的先后排：

1. **跑一次多选上游**（§2、§3）：没有它用户发不起对比，其余都无从看起。
2. **对比与信息卡**（§4–§7）：弹窗矩阵、大图切换、筛选、信息卡。

## 10. 待定事项

| 事项 | 建议 |
|---|---|
| 首页是否也提供"列 = 上游"的整页视图 | 不做：弹窗矩阵已覆盖单轮比较，走势靠筛选 |
| 显示名过长时列标题如何处理 | 两行折行，超出再截断并放全名到 `title`；不另设短名 |
| 跑一次是否允许矩阵外的合成目标 | 允许：否则每个模型 × 强度 × 上游都要在矩阵里登记一遍 |
| 信息卡是否显示模型清单 | 不显示：跑一次栏里"没有 gpt-6-sol"已经把清单用在了该用的地方 |
