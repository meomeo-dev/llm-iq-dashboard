# 看板 24 小时表盘设计 Brief

- **所属端**：Web 看板（桌面浏览器，深色主题，表盘栏宽 380–680px，正方形）
- **页面**：首页 `/` 左栏。表盘方案未采用，首页现为时间线布局，见文末“视觉参考”
- **版本**：v3 草案（分组堆叠玫瑰图）
- **依据**：`src/app/globals.css` 的 token；`README.md`「看板」一节的功能约束

## 1. 背景与现状问题

表盘回答一个问题：**今天每个钟点，各家 CLI · 模型 · 思考强度画鹈鹕画得怎么样**。
v3 的信息结构（角度不说谎、分组分段、表针指向准确分钟）已确定，视觉尚未设计。
走查截图中的问题：

1. **花瓣像散落的方块，不像花瓣**。每一层是一个深色圆环扇形，上面叠一个白底圆形
   缩略图，方与圆混杂、边缘生硬；同一小时的三段之间只有一道缝，看不出"一朵"。
2. **90% 的表盘是空的**。定时任务每 6 小时一轮，24 个扇区里通常只有 4 个有内容，
   其余 20 个扇区仍画满灰色扇区线，空处比内容更抢眼。
3. **失败层几乎不可见**。失败的层只把填充调淡，在深色底上和空扇区混在一起，
   只剩一个红圈 ✕ 悬在半空。
4. **分组色与语义色打架**。agy 段用的蓝色与选中态强调色、表针颜色同为 `--accent`
   蓝；橙色 claude 段与状态色黄 `--warn` 相近。看不出"哪些颜色是分组、哪些是状态"。
5. **表针压在花瓣边缘上**。21:59 的表针几乎贴着 21 点扇区的右边界，线与扇区线重叠。
6. **中心摘要盘过重**。直径 22% 的实心黑盘遮掉表盘中心，视觉重心落在一个空洞上。
7. **刻痕、刻度、"现在"针都很弱**。执行刻痕只有 1–2px 的短线；红色虚线"现在"针
   与失败红色同色。
8. **图例挂在表盘下方，与花瓣没有视觉连接**。分组名前的 9px 色块是唯一的对应线索。

## 2. 定位与原则

表盘是**挂在屏幕上远看的仪表**，细节留给右侧面板。

1. **位置不说谎**：角度只由真实时间决定，同一小时的多轮执行往外堆，不沿圆周挪动。
   表针指向准确分钟；每轮执行在刻度圈上有刻痕。
2. **先看成败，再看归属，最后看作品**：3 米外能看出哪几个钟点跑了、失败多不多；
   1 米内能看出哪一段是哪一家；凑近或悬停才看作品。
3. **界面让位于作品**：界面本身只用中性色，彩色只给语义。分组用明度或纹理区分，
   把色相留给状态（成功 / 无 SVG / 失败）。
4. **空即信息**：没跑的钟点要安静，不能比跑了的钟点更显眼。

## 3. 信息架构

### 3.1 数据事实

- **一轮执行（run）**：一个开始时刻 + 触发方式（定时 / 手动）+ 若干结果。
  定时轮次每 6 小时一次（00/06/12/18 点附近）；手动补跑常在几分钟内连续多次
  （如 21:47、21:51、21:59）。
- **一个结果（card）**：`cli`（agy / codex / claude）、`model`、`effort`
  （low / medium / high / xhigh / max / ultra）、`status`
  （ok / no-svg / error / timeout）、SVG 作品（仅 ok 有）、失败说明、耗时、
  文件大小、提示词（经典版 / 变量版）。
- **规模**：一轮 2–8 个目标；完整配置可达约 20 个目标。一天 4 轮定时 + 若干手动。
- **分组维度**由 tab 决定：按 CLI / 按模型 / 按思考强度。第一维度决定分段，
  其余维度决定段内顺序。

### 3.2 表盘由外向内

| 层 | 元素 | 说明 |
| --- | --- | --- |
| 小时数字 | 00 / 03 / … / 21 | 00 在正上方，顺时针 |
| 刻度圈 | 24 个小时刻度、每轮执行的刻痕、"现在"标记 | 刻痕按准确分钟落位 |
| 花瓣区 | 24 个小时扇区；有内容的扇区长出花瓣 | 花瓣 = 按分组分段 + 段内逐层 |
| 每一层 | 一个结果：状态 + 作品缩略图 | 缩略图全表盘等大 |
| 表针 | 指向所选轮次的准确分钟 | 所选轮次在花瓣上描边 |
| 中心 | 所选轮次的时间、日期·触发方式、成功 n/m | 可以比现在小、比现在轻 |

表盘下方：分组图例（每组一行，组内按段内顺序列出目标）。

### 3.3 交互

- 点任一层 → 选中该轮，右侧面板展示该轮全部结果，表针转过去。
- 悬停一层 → 放大预览作品（约 54px）。
- 悬停图例中的目标 → 只保留它的层，其余淡出。
- 切 tab → 花瓣重新分段；切日期 → 换一天；切提示词 → 只显示该提示词的结果。
- 每 60 秒自动刷新；查看今天时有"现在"标记。

## 4. 视觉与主题

仅深色主题。沿用 `src/app/globals.css` 的 token，不新造色板：

| 用途 | token |
| --- | --- |
| 页面底 / 面板 / 面板高亮 | `--bg #0f1115` / `--surface #171a21` / `--surface-hi #1e222b` |
| 描边 | `--border #2a2f3a` |
| 文字 三级 | `--text #e6e8ee` / `--text-dim #9aa2b1` / `--text-faint #6b7385` |
| 选中 / 强调 | `--accent #6ea8fe` |
| 状态 | `--ok #4ade80` / `--warn #fbbf24` / `--err #f87171` |
| 圆角 / 间距 | `--radius 10px` / `--gap 16px` |

约束：

- 分组区分不得占用状态三色与强调蓝；可用明度阶梯、描边样式或纹理。
- 表针与"现在"标记不得与花瓣共色；"现在"不得用 `--err` 红。
- 缩略图为任意配色的彩色 SVG，其容器必须是中性色。
- 表盘随栏宽 380–680px 等比缩放，最小尺寸下小时数字 ≥ 11px、缩略图 ≥ 16px。

## 5. 必须可评审状态

1. **默认态**：今天，4 轮定时 + 1 组手动补跑（3 轮相隔几分钟），按 CLI 分段，
   三组各有成功与失败。
2. **选中态**：某一轮被选中，表针、描边、中心摘要联动。
3. **空态**：当天没有执行记录。
4. **密集态**：一轮约 20 个目标，同一小时 3 轮，缩略图退化为状态点。
5. **悬停态**：某一层放大预览；某个图例目标高亮、其余淡出。
6. **按模型 / 按强度分段**：同一份数据换分段维度后的样子。

## 6. 交付与验收

交付：2K 概念图 ≥ 2 张（默认态、密集态），正方形画布，深色；
可附一张选中态局部放大。

验收（逐条可核对）：

1. 1 秒内能数出今天跑了几个钟点，并看出哪个钟点失败最多。
2. 不看图例能分辨同一花瓣里的三段属于三家；看图例能对上是哪三家。
3. 花瓣读作"一朵"：同一小时的各段有共同轮廓，段与段可分辨但不割裂。
4. 表针的针尖与 21:59 的刻痕重合，与 21 点扇区边界不重叠。
5. 空扇区安静：没有内容的钟点在 3 米外不可见，凑近可见刻度。
6. 分组用色与 `--ok / --warn / --err / --accent` 四色在色相上可区分。
7. 密集态下缩略图退化为状态点后，花瓣长度与成败分布仍可读。
8. 所有缩略图等大且为同一形状。

## 附：给 Codex 的功能描述

> 设计一个 24 小时表盘，用于展示当天每个钟点里各家 AI 命令行工具画"鹈鹕骑自行车"
> SVG 的结果。正方形深色画布。00 点在正上方，顺时针。
>
> 数据：一天有 4 轮定时执行（约 00/06/12/18 点）和若干手动补跑（常在几分钟内
> 连续 2–3 轮）。每轮有 2–20 个结果，每个结果属于一家工具（agy / codex / claude）、
> 一个模型、一个思考强度，状态为成功 / 无产出 / 失败三种之一，成功的有一张彩色
> SVG 作品。
>
> 布局规则（不可违反）：角度只表示真实时间，每小时一个扇区，同一小时内的多轮
> 结果向外堆叠而不是沿圆周挪动；每个小时的花瓣由内向外按工具分段，段内每个结果
> 占一层，各段长度等于结果数，因此长短不一；所有作品缩略图等大；一根表针指向
> 所选轮次的准确分钟，刻度圈上每轮执行有一道刻痕；中心显示所选轮次的时间与成功数。
>
> 设计要求：远看先看出哪些钟点跑了、失败多不多；近看能分辨段属于哪家；悬停或凑近
> 才看作品。界面只用中性色，色相留给状态（绿成功 / 黄无产出 / 红失败）与选中蓝，
> 工具分组用明度或纹理区分。没跑的钟点要安静。缩略图容器为中性色。
>
> 需要两张图：默认态（4 轮定时 + 3 轮手动补跑，按工具分段）与密集态
> （一轮 20 个结果、同一小时 3 轮，缩略图退化为状态点）。
